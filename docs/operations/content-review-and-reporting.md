## Content acceptance

The separate `content/drafts/initial-30.json` workspace has 30 original agent-authored B1 targets and 60 variants covering plurals, preposition/article cases, adjective endings, verb forms and subordinate word order through all five initial forms. `npm run content:review` validates the catalog and regenerates `content/drafts/REVIEW.md` for independent German-language review. Each entry contains the exact exercise, revision, answers, explanation, context/transfer identity, provenance and ambiguity notes. Validation uses generated exercise contracts and the actual deterministic grader.

Validation rejects duplicate identities, wrong target linkage, incompatible rubric answers, repeated prompts/contexts, missing initial forms, unknown fields and solutions in exercise payloads. Named reviewer/date/checklist notes and a matching SHA-256 of the target content are required for an approved record. Subsequent content edits invalidate the hash. A hash records which content was signed off; it cannot establish reviewer independence or grammatical correctness. All 30 records remain pending and publication is false. The catalog is not installed in either learner or the API; the five-target immutable fixture is preserved. Broader B2/meaning/gender coverage and the approximately 120-target pilot remain open.

## Revision-linked report flow

The generated v2 request contains report ID, owned session-question ID, revision and category. Both clients save before sending, freeze pending requests and retry only explicitly. A report can be retried after leaving practice: web uses a separate version-one fixture record; native uses additional optional fields in the existing version-one AtomicFile record. A lost response or failed receipt save keeps the original pending ID/payload. The native record survives repository restart; report writes leave drafts, assistance, answer/Skip payloads, counters and confirmed evidence unchanged. Each client holds one pending report at a time; completed reports permit a subsequent report. This is local fixture coordination, not a production account-partitioned outbox.

`POST /v2/content-reports` authenticates the subject and resolves the exercise from the owned pinned question. Migration 007 enforces the complete owned question/exercise/revision linkage and append-only rows. Exact retry returns the same receipt, changed payload conflicts, wrong ownership/revision is rejected. New reports are limited to ten per learner per rolling hour; replay precedes the limit and the exact hour boundary frees capacity. This local serialized PGlite limit is not independent-connection production contention evidence. Reports contain category only, no answer text or free-form private comments. Moderation operations, production rate-limit calibration and privacy deletion policy remain future work.

The web report is a keyboard-operable details panel with labelled categories, localized copy, existing 48px controls and alert/status feedback. Native uses the same categories and existing 48dp buttons. React review found unconditional hooks, lazy storage initialization, event-triggered writes and a submission ref lock; no new dependencies. Existing blueprint-based preview styling continues to supersede legacy navigation rules. Full visual/WCAG/TalkBack/large-font acceptance is not claimed.
