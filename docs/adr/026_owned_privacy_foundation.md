# ADR 026: Owned exports and local learner-data deletion

Accepted for the disposable v2 adapter and fixture learners, 5 October 2026.

`GET /v2/me/export` produces `learner-export-v1`: the authenticated subject, generation timestamp, current preferences, pinned sessions/exercises, raw accepted attempts, evaluations, exposure/Skip events, confirmed targets/schedules, correction reports and completion receipts. It reads a single locked transaction, includes only that subject, and does not export credentials, private grading rubrics or transport caches. Local drafts and pending requests are excluded. Both learners offer either confirmed export or an explicit whole-client sync followed by export. Failed sync stops before export; no new submission or session completion is invented. Web downloads JSON. Native uses Android's document picker and writes only to the learner-selected destination; cancellation does not remove saved work.

`DELETE /v2/me` requires the closed `PrivacyDeleteRequest` with a frozen UUID and literal `delete_owned_data` confirmation. The local adapter transaction removes every owned learner-data table in foreign-key order while leaving shared catalog/revisions intact. A transaction-local subject permits deletion through the existing immutable-row trigger only for an enumerated set of learner tables. It never permits updates or shared catalog deletion. This is privileged local-adapter machinery, not proof of production least privilege. Failure rolls back the entire deletion and its tombstone.

The remaining tombstone contains only subject, deletion-request UUID and deletion timestamp. An identical retry returns the original receipt, including after an accepted response is lost; a different UUID conflicts. Reads and writes cannot recreate the profile or replay abandoned evidence after deletion. No tombstone expiry is introduced: expiring it while host credentials still exist would permit resurrection. Production retention/privacy review must define this policy together with auth revocation and backup/log handling.

This deletes local service learner data, **not** the host identity. Production reauthentication, identity deletion/revocation, privacy review and release integration remain mandatory before enabling account deletion in a real environment. Neither client exposes deletion yet: the next slice must freeze its request durably, block other writes, provide explicit retry, and clear only the selected subject after a confirmed receipt. Sign-out must separately offer sync or explicit local removal without silently abandoning work. Do not interpret the public fixture credential as a production auth system.

Migration 010 extends the disposable development chain. Consolidate that chain into a clean v2 baseline before establishing the first real staging or production database. No operational compatibility requirement is established by these fixtures.
