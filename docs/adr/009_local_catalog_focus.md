# ADR 009: Local catalog metadata and focused practice

Accepted for the isolated demonstration, 4 October 2026.

Add authenticated, no-store `GET /v2/catalog` for the pinned unpublished foundation release. Generated v2 TypeScript/Zod and Kotlin contracts carry bilingual topic titles, target titles/descriptions, topic linkage, level and available question counts. Content presentation metadata lives under `content/foundation`, separate from the server-only grading review. No accepted forms, rubric, evidence identities or learner data enter this response. Explicit `unpublished_local_draft` status distinguishes it from the blueprint's future published `/v2/topics` service. This endpoint must not become a production publication adapter without reviewed releases, bounded pagination and release eligibility.

Extend `POST /v2/sessions` with a second strict request shape containing `focus: { type: 'target' | 'topic', id }`. Existing mixed requests remain valid without new fields. The server filters the immutable release's eligible pool through database target/skill/topic linkage before invoking the existing `mixed-selection-v1` policy. Capability filtering, retirement, learner locking, exact-count failure, immutable revisions, assessment/reinforcement roles and receipt-time evidence reduction remain shared. Unknown or incompatible focus returns `insufficient_content`; it never falls back to another pool. Focus participates in the existing owner/request-ID replay comparison; switching focus or mixed/focused mode conflicts. Replay occurs before current availability checks.

Keep one question per distinct target. The local catalog advertises at most one available question per target under this policy; topic availability counts these targets. The web requests one target question or up to five topic questions. This does not invent variants or satisfy the reviewed-content/diversity gates. Voluntary extra practice before a due deadline stays reinforcement, so it cannot increase qualifying retention checks.

Topics, topic detail and Progress target detail use metadata from this API. Target detail joins confirmed summaries by ID and labels the snapshot as previously confirmed. It shows state, qualifying checks and saved deadline rather than recalculating policy. Unfinished practice must be resumed or explicitly discarded before another focus starts. Extend the existing fixture storage request union so old mixed sessions remain readable and focused creation retries survive reload with the original ID/payload. Metadata is fetched afresh and is not an offline catalog. A failed catalog read offers retry without deleting confirmed progress or drafts.

Use existing semantic cards/actions, localized strings, light/dark tokens, 48px controls and heading focus. Three navigation actions now wrap with token-based padding at narrow widths. As in ADR 008, the blueprint intentionally supersedes legacy accuracy/streak emphasis and permanent practice navigation, Radix/CVA requirements and legacy global theme implementation. No new grading policy, content publication, production identity, native product journey or complete accessibility acceptance is established.
