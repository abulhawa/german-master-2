# ADR 012: Debug native learner shell and saved profile writes

Accepted for the local demonstration, 4 October 2026.

Add a debug-only `LearnerPreviewActivity` alongside the existing foundation entry point. Release navigation, application ID, signing configuration and legacy Room storage remain untouched. The shell uses existing generated v2 profile, catalog and confirmed-target contracts with the public loopback fixture token. It never reads raw legacy database tables or computes learner states, due dates or mastery transitions.

A separate version-one `german-master-v2-local-learner.json` AtomicFile stores the last confirmed profile, complete target snapshot, catalog and frozen pending profile request. Request UUID, expected revision and preferences are saved before HTTP. Failed writes block transmission. Lost responses, restart and acknowledgment-save failures retain the exact request for replay. After replay, reread the latest owned profile, because the original acknowledgment can predate a later preference edit. Explicit Reload current preferences obtains the current server profile before removing the pending request. Refresh preserves pending work. Corrupt or unsupported storage is preserved and blocks entry rather than resetting it.

A repository mutex serializes operations in this activity. Each refresh accumulates the complete frozen target page sequence and validates snapshot time, watermark, duplicate IDs and repeated cursors before replacing the cache atomically. No target sync cursor is committed: this slice uses fresh snapshots only. Failed refresh keeps the preceding complete snapshot. Saved due flags are shown as potentially stale until refresh; dates render server UTC deadlines in the current profile timezone. Home separates weakness targets from other due targets, avoiding double counting. Progress displays only server-confirmed Needs practice, Improving and Mastered groups. New/Learning do not become synthetic gains.

The native Material 3 shell uses shared semantic tokens, system theme, scrollable layouts, safe-area/keyboard insets, heading semantics, polite status announcements, bilingual copy and 48dp control minimums. Language/level/count selection cycles the supported options; timezone is labelled and validated before freezing. This intentionally replaces legacy analytics-first navigation only in the debug entry point. Practice is explicitly unavailable in this slice rather than connecting the standalone foundation preview as a completed learner session.

This is a shared public fixture account and a single-activity local cache, not production authentication, account partitions, cross-process coordination, full offline reconciliation or complete Android parity. Profile/catalog reads are separate requests; they are not an atomic server snapshot of preferences and catalog availability. Device/TalkBack/font-scale acceptance, reviewed content and native Practice/Skip/summary are later gates. No deployment, content publication or store release is authorized by this decision.
