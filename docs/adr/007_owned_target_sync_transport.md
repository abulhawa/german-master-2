# ADR 007: Owned confirmed reads and durable local cursors

Accepted for the isolated demonstration, 4 October 2026.

Expose `GET /v2/targets` and `GET /v2/sync` using generated v2 TypeScript/Zod and Kotlin models. Both require a verified subject from the host authentication adapter. Targets return compact confirmed summaries, including New targets without accepted evidence; the local catalog includes unpublished drafts and retired target history. Omit learner identity, raw answers, rubrics, internal evidence decisions and pending client work. Pending events remain a separate client concern.

A target snapshot takes the learner ingestion lock, captures an injected UTC instant and the latest owned sync sequence, and materializes immutable pages in target-ID order. Every page carries the same `generatedAt` and opaque `syncCursor`; `nextPageCursor` is empty at the end. Following a page cursor replays that exact stored page, even after ingestion, time changes or restart. Its original page size wins over a new limit. Clients must persist the entire snapshot before using its sync cursor; accepted writes after the watermark are then retrievable, including writes during snapshot pagination. A fresh request without a cursor creates a new snapshot.

Refresh `isDue` on fresh target reads by comparing the saved UTC `schedule.dueAt` with the captured clock (`dueAt <= generatedAt`). A clock change does not change learner state or write evidence, schedules or sync changes. One optional schedule is represented as a zero-or-one-element array. Transport instants accept canonical UTC seconds or three fractional digits, consistently in both languages; impossible dates and offsets are rejected. The contract generator now supports millisecond precision, including the server's `.000Z` representation, without truncating issuance or read time.

Sync uses opaque random UUID cursor records scoped to owner and sequence. Omitted cursor starts at zero. Read only owned changes after that position, ordered by sync sequence, with `limit + 1` lookahead. The returned `nextCursor` names the last delivered sync sequence, never the lookahead or another owner's sequence. Global sequence gaps are allowed. `lastSequence` inside a target refers separately to accepted-evidence ordering. Empty pulls retain the position. Polling the same cursor returns the same immutable historical changes, with later writes appended when room permits; page boundaries and `hasMore` may grow as ingestion continues. There is no frozen sync-wide high watermark. Apply each page and advance its cursor atomically on the client. A final cursor remains a valid polling position.

Sync payloads retain ingestion-time `isDue`, rather than silently rewriting historical meaning at retrieval. To display current eligibility, fetch a fresh target snapshot or compare the provided UTC deadline with the current clock as a presentation flag. Confirmed evidence, state and scheduling policy remain server-owned. Replaying an accepted attempt does not produce a second delta.

Migration 003 creates append-only cursor/page records and upgrades prior local databases idempotently. Unknown, foreign and wrong-kind cursors all return `invalid_cursor` without disclosing another owner. Strict HTTP query validation rejects unrecognized/repeated parameters and bounds limits to 1–100 (default 50). Reads use `no-store` caching.

This is a small-catalog local implementation. Materializing pages and retaining all cursor records indefinitely is unsuitable for production scale. Expiry/cleanup, cursor reset/full-snapshot recovery, content/account tombstones, production identity, least-privilege database roles, multi-connection PostgreSQL contention and durable client cursor commits remain explicit future gates. No production migration or client journey is introduced here.
