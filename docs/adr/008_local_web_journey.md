# ADR 008: Isolated web learner journey

Accepted for the local demonstration, 4 October 2026.

Add a development-only `/renovation` entry point alongside the foundation previews. It uses the loopback fixture API and never mounts inherited authentication, practice queues or service-worker registration. The production learner route remains unchanged. This starts M3 without claiming production readiness or closing M0/M1/M2 gates.

Home offers an explicit five-question session instead of padding the five-target unpublished catalog to fifteen. Server selection, immutable questions, grading, retention and review scheduling stay authoritative. Home counts distinct `needs_practice` targets and due targets outside that group separately, avoiding duplicate counts. No client scoring policy is introduced. Progress renders all five server states, saved review deadlines and qualifying checks; a session summary counts only acknowledged answers and server-correct outcomes, without claiming retained mastery.

Use the generated semantic foundation tokens and exercise primitives. For this reset preview the blueprint supersedes legacy streak/accuracy emphasis, permanent practice navigation and Radix/CVA requirements: focused practice hides the main navigation and settings; Home and Progress share compact native buttons. Preserve accessible labels, keyboard operation, visible focus, 48px controls, English/German copy and light/dark roles. The existing foundation maximum column width remains; inputs fill the column. Topics and target-focused sessions remain a subsequent contract/selection slice, rather than displaying unavailable controls.

Save one versioned localStorage record in `german-master-v2:local-fixture:journey-v1`, explicitly restricted to this public local fixture. The bounded five-question demo saves drafts (including partial slots/order), hint assistance, stable session request/device IDs, current position, frozen attempts, acknowledgments and summary counts. Save before creating a session or sending an attempt; show a hint only after saving assistance. A storage failure blocks the operation, keeps visible input consistent with saved data, and preserves existing records. Invalid records are preserved with a blocking recovery notice. Refresh failure retains prior confirmed data. Rejected answers never turn into feedback; the owner can explicitly discard the local preview session after a fixture server reset.

Fetch a complete frozen target snapshot before saving its watermark. Validate consistent timestamps/watermarks across pages. Pull `/v2/sync` in order; save each page's upserts and cursor in the same record before requesting another page. Never replace a later target evidence sequence with an earlier one. A fresh snapshot then refreshes UTC due flags. Do not announce stale data as a successful refresh. Interrupted sync retains the last committed page, and accepted submissions are never graded locally or counted twice on acknowledgment retry.

This is a connected, single-tab local demonstration, not downloaded offline grading, a production outbox, or authenticated account partitioning. The launcher still resets server data on restart. Concurrent browser tabs, fixture server reset recovery without manual discard, storage migrations, cursor expiry/tombstones, production identity and network PostgreSQL, and Android product parity remain open. Fixed bilingual labels cover only the pinned draft fixture and contain no solutions; publishable catalog metadata must move into versioned server contracts with content review before catalog expansion.
